# 客户电脑登录与同步修复

## 已确认的问题

生产 PostgreSQL 中，JINGHUI、FJINGHUI 的账号会话仍绑定“当前运营电脑”这台 Mac；工作区选择记录已经指向 Windows“华科未来FDE”。旧同步接口优先使用账号原绑定，导致切换添加账号的电脑后，同步仍回到 Mac。

## 本次行为

- 每个浏览器独立选择执行电脑，配对成功后自动记住新设备。每次请求都验证设备归属、撤销状态与在线连接，不继承其他浏览器的选择。
- 已有账号在另一台电脑点击同步时，在目标电脑创建新的 Chrome 登录会话。只有创作平台、网页版和目标账号编号一致，才替换账号会话；成功后网页自动继续同步。
- 所选设备离线、撤销或不属于当前客户时直接报错，所有工作区都移除回退管理电脑的路径。
- 旧电脑未完成的同账号扫码任务会取消，晚到的轮询不能改回绑定。
- 草稿执行核对当前浏览器的设备选择；尚未迁移的账号提示先到账号矩阵登录。
- 页面显示账号执行电脑、登录执行电脑及实际同步错误。

## 验证

使用实际客户 WebSocket 通道连接两个独立的测试执行服务，覆盖 Mac 旧账号迁移到 Windows、错账号不迁移、验证后采集并写入内容、草稿指令只发往 Windows、离线不回退、跨客户拒绝、独立浏览器选择。

前端测试验证同步进入扫码流程、扫码成功后用登录任务固定的设备继续同步、二维码轮询稳定及错误提示。完整回归 242 项通过，1 项旧测试假定无需设备即可批量执行；将该测试明确为草稿生命周期测试后，与完整双设备测试重新运行均通过。另有 6 项依赖外部环境的测试跳过。TypeScript 与生产网页构建通过。

发行镜像：`matrix-cloud:20260917-customer-computer-v2`，镜像摘要 `sha256:bc4e562e031c27bc8b3bf7a68bf103fa2829a2102ce4f2537047b1a99ba3b79f`。连接器保持已发布的 3.0.1 ZIP，本次不需要重装。

## 验证边界

上述双设备测试使用模拟小红书数据，验证真实传输、身份检查和持久化流程。用户 Windows 在本轮离线，用户表示暂时无法连接，因此真实 Windows 上的小红书扫码、实际采集结果及实际草稿保存仍待该电脑恢复在线后验证，不能据此宣称所有客户环境已验收。
