# 矩阵云：文件与代码删除指南

适用目录：桌面 `MatrixCloud-Separated`。原项目 `MatrixCloud-Dev` 完整保留，不能因为新目录能打开，就删除原目录中的数据库、素材、登录状态、密钥和回滚包。本次完成源码拆分，没有执行生产数据迁移，也没有上线。

## 现在的目录职责

| 目录/文件 | 用途 | 删除结论 |
|---|---|---|
| `frontend/src/` | 页面、交互、样式 | 页面在使用的源码不能删除；下面列出两项未启用组件候选 |
| `frontend/index.html` | 浏览器入口，加载 main.tsx | 必须保留 |
| `frontend/package.json`、`vite.config.ts`、`tsconfig.json` | 前端依赖、代理、构建 | 必须保留 |
| `backend/server/` | API、认证、同步、任务、业务存储和维护代码 | 正在运行或由命令启动的代码必须保留 |
| `backend/package.json`、`vitest.config.ts`、`tsconfig.json` | 后端依赖、检查和测试 | 开发源项目必须保留 |
| `shared/` | 账号/内容类型、模板、恢复规则、连接器协议 | 必须保留；前端、后端、连接器都可能引用 |
| `scripts/` | 执行器、浏览器动作、启动、打包、备份与迁移 | 不能整目录删除；按下表区分 |
| `local-connector/` | 客户电脑与浏览器执行链路 | 保留现有同步和草稿功能就必须保留 |
| `workbuddy-connector/` | WorkBuddy 配套配置、说明和图标 | 仅停用 WorkBuddy 交付时可删；后端 MCP 入口另行保留 |
| `deploy/`、`Dockerfile`、`frontend/Dockerfile`、`frontend/nginx.conf`、`compose*.yaml` | 两个服务的容器部署、入口和维护服务 | 使用该部署方式必须保留 |
| 根目录 `package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`tsconfig.base.json` | 工作区、依赖版本和公共编译选项 | 必须保留 |
| `SOURCE-SNAPSHOT.json` | 原源码哈希和来源 | 运行不依赖，验收和追溯期间保留 |
| `.git/`、`.gitignore` | 版本、回退和私密/生成文件忽略规则 | 开发维护应保留；删除 .git 会丢失本副本提交和维护功能 |

## 可以重新生成的文件

停止正在使用这些目录的开发/构建进程后，可按需删除；它们不包含必须手写保留的代码。

| 文件/目录 | 删除后影响 | 恢复方法 |
|---|---|---|
| 根、前端、后端 `node_modules/` | 暂时无法启动、测试、构建 | 在根目录 `pnpm install --frozen-lockfile` |
| `frontend/dist/` | 构建产物不存在，静态生产前端无法启动 | `pnpm --dir frontend build`；开发 Vite 可直接运行 |
| 原项目 `dist/` | 旧结构的前端构建产物 | 原项目仍用于提供页面时先保留；下线后可删并重新构建 |
| `*.tsbuildinfo`、`node_modules/.vite/`、`.cache/`、`__pycache__/`、`*.pyc` | 仅丢失编译/测试缓存 | 下次检查自动生成 |
| 测试日志，如 `baseline-tests.log`、`separated-tests.log`、`verified-tests.log` | 丢失本次详细检查日志 | 已记录摘要后可删；不要把业务审计日志一起删 |
| 新副本 `work/separation-qa-artifacts/` | 丢失本轮合成测试账号和数据 | 确认没有投入真实使用后可删；这是本轮独立产生的测试数据 |

`node_modules/` 里看起来也是代码，但它们是通过锁文件安装的第三方代码，不需要逐个保留。**pnpm-lock.yaml 是恢复依据，不能随依赖目录一起删。**

## 当前可以删除的代码候选

这些文件本次仅标记，没有替你删除。分析基于当前入口 `frontend/src/main.tsx` 的递归导入、后端入口/运维命令和项目文本检索，不能代替外部客户端配置检查。

| 代码 | 当前证据 | 删除条件 |
|---|---|---|
| `frontend/src/CreationCenter.tsx` | main.tsx → GreyApp 的页面导入链未到达它；当前实际创作使用 OneClickPublish/PublishCenter；未发现其他代码引用 | 没有计划恢复旧 CreationCenter 页面时可删除，然后构建和跑前端测试 |
| `frontend/src/SyncGuide.tsx` | 当前页面入口没有引用；只留在历史开发记录中 | 不恢复旧手动说明页面时可删除；不要删除仍被其他页面使用的 safe-clipboard.ts |
| `backend/server/xhs-qr-login.ts` | 当前后端入口导入链没有引用，历史桥接扫码实现；当前 grey-app 扫码路由仍存在 | 确认外部工具未直接导入 createQrLogin、也不再维护旧浏览器桥接扫码后再删；`scripts/xhs-qr-login.mjs` 是另一个文件，需独立检查 |
| `backend/server/grey-proxy.ts` | 独立 stdio MCP 桥接入口，没有页面导入不代表没用途 | 确认所有 MCP 客户端都已使用现有 workbuddy-mcp 或其他入口，且配置没有指向它后可删 |
| `scripts/phase-two-async.mjs` | 一次性源码转换工具，不是运行时入口 | 已完成转换、无需再复用补丁转换时可删 |
| `scripts/verify-*.mjs`、`scripts/diagnose-reference-service.ts` | 人工诊断、速度/界面验收工具，不是普通页面启动依赖 | 不再需要对应核验或维护诊断时可删；仍需要验证时保留 |
| `railway.json`、`render.yaml` | 平台特定的部署模板 | 当前完全不使用这些平台时可删；不影响两个 Dockerfile 和 Compose 部署 |
| 历史截图、旧计划、过期交付说明 | 普通运行不读取 | 已保存必要验收/回滚证据后可归档；删除不会简化业务依赖 |

未发现当前前端使用 `recharts`、`tailwindcss`、`autoprefixer`，也没有对应配置引用。它们是**可评估移除的直接依赖声明**，不是现在必须删除的源码。确认不用后，通过 pnpm remove 从 frontend/package.json 和锁文件同步移除，再构建验证；不要只手改锁文件。`postcss` 仍可能由 Vite 间接使用，不能据此直接删除整个相关依赖树。

## 数据和私密文件不能按源码规则删除

原项目中的 `work/`、`.handoff/`、真实 `*.sqlite`/`*.db`、上传图片和视频、媒体/模板目录、浏览器 Profile、Cookie、账号配对凭证、`access-token`、`connector-token`、`model-encryption-key`、私钥、`.env*`、PostgreSQL 卷、必要回滚镜像和备份，不是缓存。没有逐项备份和引用核对不能删除。`outputs/` 混有客户包、验收和回滚证据，不能整目录一刀切。

本副本的测试账号和本机数据是新生成的合成数据；你的已有账号、素材和历史任务没有被带入测试。正式迁移请按 `migration/` 和运维文档操作。

## 拆分时已处理的旧代码

原来后端提供前端静态文件的两行已移除：

```ts
app.use(express.static(distDir));
app.get('/', (_, res) => res.sendFile(join(distDir, 'index.html')));
```

前端对 `../server/domain` 和 `../server/creation-queue` 的类型依赖已经改为 `shared/domain` 和 `shared/creation`。原根目录 `src/`、`server/`、`index.html`、`vite.config.ts` 在**新副本中**已迁到相应子目录，不需要再复制一份留在根目录。原项目中的同名文件仍保留。

## 建议的清理顺序

1. 先保留源码、锁文件、运行配置、真实数据和回滚包。
2. 停止当前开发服务，按需移除构建产物、依赖和缓存。
3. 对明确未启用的组件逐个删除，检查构建和相关测试。
4. 可选功能先确认外部配置和人工工具不用，再删除整条功能链。
5. 最后处理历史交付包和素材；素材必须依引用清单受控清理。

[逐文件清单](file-deletion-inventory.csv)提供每个源码文件的结论和理由，[依赖分析](dependency-analysis.json)记录当前静态导入关系。未列为明确候选的业务代码按保留处理。
