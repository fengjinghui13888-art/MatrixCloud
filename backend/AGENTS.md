# Python 维护约定

先执行 `python tools/maintenance_context.py` 获取有限上下文，再读取目标模块。项目根仅 frontend/backend；后端入口 run.py，API app/api.py，业务 app/services.py，连接器 connector。

保留业务供应商、模型、原费用和默认值、素材二创与所有已上传原图；单任务1–12张。不要引入降本预算/收费拦截或缓存替代新任务。协议4、租户/设备隔离、取消、限速、限制暂停、结果未知不重复上传必须保留。

发布中心自动生成的文案必须保持小红书笔记整体风格：自然口语化、短句短段、具体标题与相关话题标签，避免公文腔与硬广告。emoji 可有可无、少量自然点缀；表达随选题人设变化，不固定模板。自定义 style 只补充、不覆盖这一基础要求；不编造亲身经历或效果承诺。

SaaS 客户端稳定启动器在 client，执行逻辑在 connector。首次安装后走签名更新；更新仅在任务空闲且安全停止已确认后切换，坏版本和未确认升级都须回退。更新/安装不得覆盖客户凭证或 Chrome 登录目录，私有签名密钥不进包。未签名本地安装器不能作为生产客户端公开；Mac 原生构建、签名和实机证据需另验。

测试使用临时数据、合成图片与本机模拟传输；真实账号、供应商调用、PG、Docker和各平台实机需另记证据，不得由模拟结果宣称全流程通过。修改后只运行相关检查；全部完成再一次集中复验。

用户已明确要求清除旧项目、重复备份与旧包；独有业务数据和原 Git 历史集中保留在 backend/data/recovery，当前版本由 .git 保存。不删除有效数据、凭证或登录配置。清理必须先预览并校验引用和哈希。部署必须展示精确提交、两镜像与测试结果，用户明确确认后才可上线；维护MCP不能替AI自我授权。
