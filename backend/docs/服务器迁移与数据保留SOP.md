# 服务器迁移与数据保留

矩阵云客户工作台与独立平台管理后台都部署到服务器，沿用 React / TypeScript / Vite 前端、Python / FastAPI 后端、PostgreSQL 数据库。前后端源码仍放在 frontend、backend。管理后台通过 `/admin.html` 访问，客户入口为 `/`，两者使用独立登录会话和权限。

## 数据保留范围

本地测试也是已有数据，不自动清除、不重建用户、不删除旧工作区。保留全部客户与管理员账号的密码哈希、权限、账号绑定、笔记、私信、评论、线索与跟进、创作任务、草稿状态、模型配置、原始素材和操作记录。保持原用户名、客户工作区编号与数据关联；密码沿用当前密码。

仅搬源码或启动空 PostgreSQL 不能恢复这些信息。必须同时搬迁 PostgreSQL 自定义格式备份和 backend/data/work/grey 的必要运行文件，特别是 model-encryption-key、platform-owner、workspaces、template-uploads 和素材文件。密钥或素材缺失会造成配置无法解密或图片打不开。

Windows Chrome 登录目录留在原电脑，不能直接作为 Linux 服务器或 Mac 的登录环境。连接器继续运行在客户电脑，通过服务器地址重新授权；必要时重新扫码。保留数据不代表原浏览器会话跨系统可用。执行锁不恢复为运行状态；正在执行或结果未知的任务应先核实结果，避免迁移后重复上传。

## 正式切换步骤

1. 确认服务器、正式访问地址、最终源码提交和前后端两镜像。先安排维护窗口，暂停新增写入及连接器任务，记录未完成任务。
2. 最终导出 PostgreSQL，并同时备份运行目录与文件哈希。保留原数据库和原电脑目录，确认备份可恢复再切换。
3. 在服务器创建独立数据库与受限应用账号，使用 pg_restore 恢复到空目标库。禁止对已有数据使用 --clean、初始化脚本或重跑旧 SQLite 迁移；不要再次运行 bootstrap_admin 创建另一位超级管理员。
4. 按当前 SQL 版本检查 schema_migration 已包含 2、3、4，配置受限应用角色权限。恢复运行文件至持久卷 /app/data/work/grey。不要照搬 Windows 数据库 URL 或路径，服务器需单独配置 DATABASE_URL、PUBLIC_ORIGIN、PLATFORM_ADMIN_USERNAME=matrix-admin 等实际参数。
5. 后端数据与 PostgreSQL 必须使用持久卷。现有 compose.prod.example.yaml 的 matrix-backend、matrix-postgres 卷负责保留数据；不要执行 docker compose down -v。前端只能访问 API，不持有数据库口令或模型密钥。
6. 先在受控地址验收：原账号登录、客户工作区及各表数量一致、素材可见、模型配置能解密、管理员与子管理员权限正确、恢复密码链路通过、连接器重新授权成功。仅模拟测试不能替代实际平台同步与草稿验收。
7. 展示最终提交、前后端镜像与检查结果，由项目负责人明确确认后才正式切流。切换后新增服务器数据，回滚前需备份并核对这些新增记录，不能直接用旧快照覆盖。

## 忘记密码

客户登录页点击“忘记密码？”。管理员在管理后台“客户管理”找到原账号，核实身份后签发 15 分钟一次性恢复码；客户自行重设后继续使用原工作区，内容和配置保留。子管理员须获“查看客户”和“协助找回客户密码”权限。当前为人工核实后发码，不包含邮箱或短信自动发送。详见《忘记密码与账号恢复SOP》。

本次仅完成本地备份恢复验证和相关功能检查，尚未上传或部署服务器。
