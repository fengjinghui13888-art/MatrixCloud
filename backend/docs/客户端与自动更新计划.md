# 云端 SaaS 客户端实施与验收计划

需求：客户只首次安装连接器，网页/服务端更新不要求重新下载 ZIP；本机登录与平台会话仍保存在客户电脑。正式域名未购买，先使用本地地址验收。

结构：frontend 只管理网页；backend/client 为稳定启动器和签名更新器，backend/connector 为可更新的执行逻辑。客户端每次启动并定时检查更新；运行中任务阻止切换；失败更新回退已验证版本。业务数据、浏览器登录目录和安装程序目录分离。

- [x] 签名发布与更新：Ed25519 校验、HTTPS 同源下载、大小/路径/文件哈希检查、版本防降级，拒绝不匹配运行时。
- [x] 常驻启动器：首次安装到用户目录、授权入口、后台工作进程、健康检查、空闲时更新、失败回退；客户无需安装 Python 的 Windows 可执行文件。
- [x] 服务端和网页：提供安装文件/签名更新清单，兼容协议 4，不把平台凭据交给前端；忙碌状态和安全退出接口仅对本机凭据开放。
- [x] Windows 本地验收：安装到隔离目录、首次授权流程、真实连接器健康、升级与回退、忙碌时不重启、篡改更新拒绝；真实 MOYA 登录与合成草稿 filled；184 后端测试通过（专用 PG 9 跳过）、98 前端测试通过。
- [ ] Mac Intel：在 Mac 构建签名与实机验收，不能用 Windows 测试冒充。
- [ ] 正式域名/TLS、系统代码签名、真实供应商模型生成和云服务器验收；缺少域名/签名凭证/模型配置，本轮未执行上线。

发行界限：代码签名/公证、正式 HTTPS 域名、线上发布及真实生成/草稿写入仍需要各自证据。开发更新签名密钥保存在 backend/data 内，不提交仓库，不在页面展示。
