# 文件与代码删除指南

当前项目根目录仅保留 frontend 和 backend 两个可见文件夹。配套文件归入其中，隐藏 .git 保存版本记录。原 MatrixCloud-Dev 未改动，旧 Node 后端和拆分前资料另有迁移备份。

## 不能删除

| 位置 | 用途 |
| --- | --- |
| frontend/src、frontend/contracts、frontend/index.html | 页面、样式、数据契约 |
| frontend/package.json、pnpm-lock.yaml、tsconfig.json、vite.config.ts | 安装、编译、代理配置 |
| backend/app | Python API、登录、存储、任务、模型、MCP、维护功能 |
| backend/connector | Python 本机连接器、浏览器登录、同步、草稿与保护机制 |
| backend/run.py、requirements.txt、requirements-lock.txt、START-*.bat、SETUP.bat | 入口与依赖锁定；批处理依赖本目录文件 |
| backend/data | 用户数据库、素材、登录配置、凭证和运行记录 |
| backend/data 内 model-encryption-key、model-settings.enc、platform-owner、access-token、connector-token、cloud-device.json | 原配置与授权；删除会导致无法解密或失去授权 |
| backend/data 内 local-connector、local-logins、browser-profiles、workspaces、template-uploads、media | 登录、客户工作区和原始图片；不要手动清理 |
| .git（隐藏） | 提交历史、GitHub 关联、回滚 |

backend/data/legacy-root 是整理前散落在根目录的数据库与目录。完整保留，未混入其他工作区；请核对实际用途后再选择 DATA_DIR，不能因为当前默认入口没读取它就删除。

## 可以重新生成

- frontend/node_modules：删除后执行 `pnpm install --frozen-lockfile`，此前不能启动前端。
- frontend/dist：删除后执行 `pnpm build`，此前不能使用生产静态文件。
- backend/.venv：删除后使用 Python 3.13 重新创建并安装 requirements.txt，此前不能启动后端。
- __pycache__、.pytest_cache、*.pyc、*.tsbuildinfo：缓存，可清理。

## 按需保留

- backend/tests、frontend 的测试：运行服务不直接依赖，但保留以防后续修改破坏功能。
- backend/tools：备份、迁移、打包、媒体核对和维护工具；不建议整目录删除。
- backend/sql、backend/deploy、compose 文件：本机 SQLite 启动不依赖；PostgreSQL/容器/维护部署需要。
- backend/integration：WorkBuddy/MCP 配置与技能。yingdao.local.json 是本机配置，未提交 GitHub。
- backend/docs：启动、迁移与历史记录；历史记录明确标注为旧版证据。

## 已移出当前代码

旧 backend/server 的 Node/TypeScript 实现、旧 local-connector/*.mjs、后端 shared 协议、根目录 workspace 依赖和旧 Node 启动器，已由 Python 实现替代。它们保存在项目外迁移备份，当前启动不读取旧代码。

业务供应商、原费用设置、单任务1–12张和已上传素材不属于清理范围。本次不进行媒体垃圾回收，不删除用户数据、浏览器配置或加密密钥。
