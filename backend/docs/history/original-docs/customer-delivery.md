# 矩阵云客户交付与验收

客户使用线上工作台，自行创建账号；每个新账号获得独立工作区。换电脑时登录同一个矩阵云账号即可看到原工作区，不需要重新注册。客户自己的团队管理员可以添加团队成员。

## 客户第一次使用

1. 打开矩阵云工作台，点击“创建新账号”，设置账号和密码。
2. 在“账号矩阵 → 连接你的电脑”下载对应系统与芯片的连接器，将ZIP完整解压。
3. Windows双击 `START-CONNECTOR.bat`；Mac双击 `启动连接器.command`；Linux在终端运行 `bash START-CONNECTOR.sh`。
4. 连接器会打开授权页。使用刚创建的矩阵云账号登录，点击“授权连接这台电脑”。连接器窗口保持运行。
5. 在工作台选择该电脑，添加小红书账号，在打开的浏览器内扫码。每个小红书账号分别验证登录；同步进度、排队和失败原因分别显示。

执行电脑需要安装Chrome或Edge；Linux可使用系统Chromium。连接器内置Node和运行依赖，客户无需安装开发工具。工作台可以在其他电脑上登录查看，执行任务的电脑须保持联网与运行。验证码、登录失效或平台限制需要客户按提示处理。

新客户的文案与生图服务配置为空，由客户在模型设置中配置自己获授权的服务；不继承平台或其他客户的密钥和费用设置。唯一管理员忘记密码目前需要维护人员恢复，尚无邮件找回入口。注册与登录有防滥用限流；大量客户在同一公网IP集中开户时应分批安排。

## 平台范围

以下是连接器的运行时基础范围，实际交付需在对应系统验收。工作台兼容性和小红书执行兼容性分别验证，不能用“网页能打开”代替连接器任务验收。

| 包类型 | 运行时基础范围 | 本轮验收方式 |
| --- | --- | --- |
| Windows x64 | Windows10/11，64位 | 当前Windows电脑解压与独立启动实测 |
| Windows ARM64 | Windows10/11，ARM64 | 构建候选，待ARM电脑实测 |
| Windows x86 | Windows10，32位 | 构建候选，待32位系统实测 |
| Mac Intel | macOS11及以上，Intel | 构建候选，待Mac签名与实机验收 |
| Mac Apple芯片 | macOS11及以上，ARM64 | 构建候选，待Mac签名与实机验收 |
| Linux x64 | 内核4.18+、glibc2.28+ | 构建候选，待桌面Linux实测 |
| Linux ARM64 | 内核4.18+、glibc2.28+ | 构建候选，待ARM桌面Linux实测 |

基础范围依据 [Node22.14官方平台说明](https://github.com/nodejs/node/blob/v22.14.0/BUILDING.md)。系统和浏览器本身仍须受供应商支持；Windows7/8、macOS10及更旧系统不属于本轮支持范围。不能保证任意老旧电脑、企业安全策略或浏览器扩展环境均可执行。

## 发布验收

- 公共注册始终创建UUID工作区；只有服务器本机 `/api/auth/setup` 能初始化平台owner。既有账号和工作区保持原归属。
- 新密码至少12字符、UTF-8最多72字节；登录保留旧scrypt长密码兼容。账号重复、网络超时会显示明确提示。
- 隔离测试覆盖真实PostgreSQL应用角色、并发注册、跨客户读取、owner数据不可见、同账号另一个客户端登录及客户设备授权。
- 每个平台ZIP带逐文件SHA256清单、运行时版本、依赖版本和固定HTTPS入口。Mac正式发布必须通过macOS的codesign验证，开发候选不能进入正式下载目录。
- 本轮正式目录仅放已完成当前Windows x64本机启动检查的包；其他包在单独的candidates目录。安装包启动成功仍不等同真实小红书同步或草稿已验收。
- 线上部署后须重新验证公网注册、另一浏览器登录、下载、配对、正常小红书账号同步与草稿；单台电脑或模拟浏览器结果不能替代这些步骤。

## 当前交付状态

本轮产物是客户交付候选和维护更新包。服务器HTTPS目前可用，但现有SSH维护连接无法建立，因此未部署本轮版本、未重启云服务器。公网客户流程、其他系统实机、Mac正式签名及真实小红书任务仍待验收。完整机器可读证据随产物提供；缺少真实结果时不标记“已上线”或“所有电脑通过”。

维护包只包含源码、说明和已选连接器，不包含生产数据库、密钥或浏览器登录状态。部署必须保留已有数据库、媒体、用户账号与模型加密密钥，生产数据迁移另走受控备份流程。
