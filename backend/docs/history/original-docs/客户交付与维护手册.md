## 1. 产品结构与交付边界

网站部署在服务器，用户注册/登录后只能访问自己的工作区。公网首页可访问不等于匿名访问客户内容；客户数据接口必须鉴权。

当前结构是：客户网页 → 云端网站/工作区存储 → 已配对执行设备 → 该账号的独立 Chrome 会话。执行设备负责采集，云端接收进度与结果；图片和视频经过大小、SHA-256 校验后进入云端媒体目录。

执行电脑由每个浏览器单独选择，保存在当前浏览器的 HttpOnly Cookie 中，并在每次执行前核对工作区归属和在线状态。旧的工作区全局选择不再决定网页执行位置。旧账号在另一台电脑点击同步时，会在所选电脑打开新登录窗口，核对创作平台、网页版和目标账号编号一致后再更新绑定，并自动继续同步。所选电脑离线或撤销会明确报错；所有工作区都不再回退到管理 Mac。草稿执行也核对当前浏览器的选择，账号尚未迁移时提示先到账号矩阵登录。

当前公网入口：https://47.106.94.169/

客户执行电脑通过主动 WSS 连接云端，不需要开放入站端口或 SSH。电脑休眠、断网、退出连接器或小红书登录过期会影响采集，但已保存内容应继续可读。

每个工作区可以配对自己的 Mac 或 Windows 执行电脑；设备令牌按工作区保存，可在连接设置中撤销。账号的 Chrome Profile 留在执行电脑上，云端只保存任务和同步结果，不上传小红书 Cookie。

面向公众收费交付还需要：自有域名与 HTTPS、密码找回、限额/容量管理、审计与告警、备份恢复演练、客户授权流程。当前 IP 的 HTTP 地址不作为最终的账号凭据交付入口。

## 2. 同步逻辑

- 云端创建任务后立即返回任务编号；采集由浏览器所在设备执行，不连接云服务器的本机浏览器端口。
- 同一账号只允许运行一个同步任务；同一执行设备最多同时采集两个账号，避免 Chrome 被无限启动。超额请求明确报告设备繁忙，当前未实现持久化排队调度。
- 先核对账号身份，再保存已读列表与详情；页面每隔数秒刷新已保存内容，无须等所有视频下载结束。
- 已完整保存的内容可以跳过详情；正文/媒体地址缺失的旧记录仍需要补采。增量检查不能承诺每次刷新全部旧帖评论与所有历史消息。
- 未读完历史、媒体失败或登录过期必须显示部分完成/需要重新授权，不能把未读到的值当作 0。
- 执行设备采集 8 分钟上限、云端整个任务 10 分钟上限，防止无限等待。超过时限保留已写入内容，需要重新同步；尚未实现精确到分页游标的断点续传。
- 用户可停止同步。重启时旧的运行中任务转为中断状态，不会永久占用同步按钮。
- 网站升级后的“同步”分两件事：已保存数据从原数据卷直接读取；新增小红书内容还需要执行设备在线和有效扫码授权。

不得用开发电脑的数据库覆盖运行中的生产数据。升级只更换应用镜像并挂载原数据目录；本次升级没有修改表结构。后续有数据库结构变更时需要版本化迁移、旧数据兼容测试及配套回滚流程，不能直接覆盖库文件。

当前生产使用 PostgreSQL 按实体存储，并对业务表启用租户隔离。升级使用 `scripts/deploy-existing.py --postgres` 同时备份文件目录和 PostgreSQL。下文 SQLite 维护命令仅适用于旧的 SQLite 部署；不得用它单独备份、恢复或清理当前 PostgreSQL 生产数据。

## 4. 备份与恢复（已提供工具）

工具 scripts/maintenance.py 使用 Python 标准库。操作路径参数可替换，Windows 用 py 或 Python 3 安装路径，macOS/Linux 用 python3。备份使用 SQLite backup API 并进行 quick_check 与逐文件 SHA-256 校验。

备份前停止网站和执行器写入，再运行：

```sh
python3 scripts/maintenance.py backup /path/to/data /path/to/private-backup/new-version --offline
python3 scripts/maintenance.py verify /path/to/private-backup/new-version
python3 scripts/maintenance.py restore /path/to/private-backup/new-version /path/to/new-empty-data --offline
```

恢复拒绝覆盖已存在目录。先恢复到新目录，核对账号数/工作区数/内容数/图片/视频，确认后再把服务挂载切到新目录。备份包括私有数据和加密密钥，目录权限仅是本机访问保护，备份包本身未加密；异地传输与存储需使用加密通道和受限存储，不能把它当作客户安装包公开下载。

建议维护制度（不是已经配置的自动任务）：

| 频率 | 操作 | 验收 |
|---|---|---|
| 每日 | 数据与媒体备份，独立位置保留副本 | 备份完整性校验通过 |
| 每次升级前 | 停止新任务，备份，记录旧镜像编号 | 可切回旧镜像与兼容数据 |
| 每周 | 检查容量、失败任务、配对状态、备份可用性 | 没有长期运行中任务 |
| 每月 | 在独立目录恢复一次 | 原账号可登录，内容与媒体可读 |
| 每次发布 | 登录/注册、双工作区隔离、同步失败恢复、媒体读取、取消验证 | 才能交付客户 |

可采用每日 7 份、每周 4 份、每月 3 份的保留策略；容量和恢复时间需根据真实客户数据量调整。当前没有自动配置定时备份、短信告警或 SLA。

## 5. 冗余数据如何清理

“旧数据”不等于“无用数据”。客户笔记、线索、跟进记录、账号密钥不能因为日期旧就删除。

删除笔记/账号只操作本系统已保存数据，不代表删除小红书原帖。后续同步可能重新采集原帖；如要永久排除，需要另做排除列表。

孤立媒体清理工具默认只报告，不删除：

```sh
python3 scripts/maintenance.py audit-media /path/to/data --days 7
```

它逐工作区读取数据库引用，保护仍被引用的媒体和索引侧文件，并跳过 7 天内的新文件。数据库不可读取时直接报错，不能当作空库清理。

确认报告、停止网站与执行器、备份后，可移入独立隔离目录：

```sh
python3 scripts/maintenance.py quarantine /path/to/data /path/to/private-quarantine/new-batch --days 7 --offline
```

隔离操作保留原相对路径与清单，不立即永久删除。保留至少 7 天、确认内容可正常读取后，由维护人员处理隔离目录。该工具不清理浏览器登录目录，也不判断客户业务记录“是否无用”。

Chrome 缓存、连接器临时采集媒体、日志和同步证据还需要单独保留策略；当前工具未覆盖这些目录。对 SQLite 回收空间需在维护窗口执行，不能把 VACUUM 当作业务数据清理。

## 6. 换电脑/服务器迁移

### 只换管理电脑

直接在新电脑打开网站并登录；云端用户和数据不需要搬动。若旧电脑兼任执行器，仍需以下执行器迁移。

### 新增或更换执行电脑（Mac/Windows）

1. 在客户电脑打开工作台的“账号矩阵”，确认地址是 `https://47.106.94.169/`，点击“下载 ZIP”，按电脑选择 Windows 10/11、Mac Apple 芯片或 Mac Intel 包。
2. 把 ZIP 完整解压到固定目录。不要在压缩包预览窗口里直接双击，也不要把下载文件改名为 `.txt`。Windows 双击 `START-CONNECTOR.bat`；Mac 双击“启动连接器.command”。
3. 首次运行会自动打开工作台授权页；成员登录自己的团队账号并点击“授权连接这台电脑”，无需输入 HTTPS 地址、端口或配对码。设备被撤销、配对文件丢失或需要恢复时，Windows 再使用 `PAIR-CONNECTOR.bat`、Mac 再使用 `PAIR-CONNECTOR.command` 输入一次性配对码（5 分钟有效且只能使用一次）。
4. 回到工作台，等待设备显示“任务通道已连接”。同一台电脑的连接器窗口必须保持运行；连接器已包含 Node.js、`playwright-core` 和 `ws`，客户不需要执行 npm install。
5. 在当前浏览器点击目标电脑旁的“在这台电脑执行”。新配对成功后会自动选中刚配对的电脑；已有多台电脑时必须明确选择。该选择不会更改其他电脑浏览器的选择。
6. 新账号点击“扫码添加账号”；已有账号直接点击“同步此账号”。账号尚未在所选电脑登录或登录过期时，会打开该电脑的新 Chrome 窗口，并在工作台显示对应二维码。按提示完成创作平台和网页版登录，身份验证成功后自动同步。
7. 账号卡片显示当前账号执行电脑。执行电脑离线时启动那台电脑的连接器；若要改用新电脑，先选择新电脑并重新扫码。发布中心会将审核后的内容保存为小红书草稿；公开发布仍需人工在小红书页面确认。

工作台中还可看到设备在线状态、撤销设备和下载包。旧电脑可以暂时保持在线，账号完成新电脑身份核验后再撤销；不要让同一个账号同时绑定两台设备。

### 整体搬到新服务器

1. 停止写入，使用维护工具备份生产数据；代码发行包与私有数据包分开传输。
2. 新服务器构建相同版本镜像，恢复到新数据目录，挂载为 /app/work/grey。
3. 配置 PUBLIC_ORIGIN 为最终公网源地址，保持模型加密密钥/数据库同时恢复。路径改变不应改变用户工作区 ID。
4. 重新配置执行设备配对及新地址；旧服务器停止写入后再切换域名解析。
5. 分别验证原账号登录、两个用户互相不可读、历史媒体、重新扫码、同步进度、失败可重试。
6. 保留旧镜像与备份到验收结束；恢复旧数据会丢掉备份后新增写入，回滚前需明确处理这些新增数据。

生成不含生产数据的代码包：

```sh
python3 scripts/maintenance.py package /path/to/project /path/to/matrix-cloud-release.zip
```

发行包不包含 work、node_modules、.env、数据备份或浏览器配置；依赖必须在新机器重装。当前源码仍含历史工具模块，不能将“前端不显示旧名称”描述为“后端代码已彻底移除旧集成”。
