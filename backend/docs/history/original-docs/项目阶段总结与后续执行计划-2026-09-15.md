## 二、已上线并验证的内容

### 1. 公网与连接器

- HTTPS 公网工作台，原 HTTP 4174 地址自动跳转。
- 客户连接器通过主动 WSS 通道接收任务，无需客户开放入站端口。
- 配对码、设备归属、设备撤销、账号与浏览器 Profile 隔离。
- 同一执行电脑的同步队列并发上限为 1：后续账号排队，前一个完成后自动执行。
- 草稿保存有独立的串行队列；同步队列与草稿队列尚不是统一的全设备调度器，不能宣称所有类型任务之间都完全串行。
- 连接器仍需执行电脑在线，电脑休眠、断网或平台登录失效会影响执行。

### 2. 数据库与权限

- 云端采用 PostgreSQL 16，schema 2，不是 MySQL，也不是托管数据库。
- 账号、笔记、评论/私信、线索、任务、媒体元数据等按实体分表保存。
- 租户业务记录带 tenant_id，实施复合约束和行级隔离；租户取自登录身份。
- 同租户支持管理员、运营、仅看线索角色；成员可停用、重设密码。
- 新密码使用 bcrypt；旧密码兼容并在正确登录后安全迁移。
- 模型配置 AES-256-GCM 加密，前端不返回完整密钥。
- 数据库不对公网开放，应用角色无数据库管理员权限。
- 原账号、登录状态、历史数据和模型配置保留；迁移重跑不会用旧 SQLite 覆盖新数据。

### 3. 实际流程验收

| 流程 | 实测结果 |
|---|---|
| 双账号同步 | FJINGHUI：1 篇笔记、1 条私信；JINGHUI：7 篇笔记、2 条评论、11 条私信 |
| 媒体复用 | 最后一轮 29 个媒体文件命中缓存，无传输失败 |
| 批量账号排队 | 第二个账号显示 queued，前一个完成后自动继续 |
| 线索删除 | 删除后来源恢复可创建状态，可再次创建 |
| 双账号草稿 | 两账号验收稿均在实际浏览器草稿箱核对通过 |
| 模型调用 | 当前已配置服务真实生成文案及一张图片，并保存到 JINGHUI 草稿 |
| 升级与恢复 | 迁移核对、独立库恢复演练、应用重建前后核心数据哈希核对通过 |

测试只保存草稿，没有公开发布。平台网页版草稿保存在执行电脑的对应浏览器内，不会自动出现在手机或另一台电脑。

同步结果仍标记 partial，因为没有证明覆盖全部历史与所有消息类型。一次成功也不代表所有账号、所有网络条件都满足时延目标；本轮有一条草稿用时 19.5 秒。

当前配置里第三方服务声明的生图型号，不能仅凭其返回图片独立证明底层官方型号。

## 三、数据究竟存在哪里，会不会放不下

| 数据 | 当前实际位置 | 规划位置 |
|---|---|---|
| 账号、正文、评论、私信、线索、任务 | 云端 PostgreSQL | 继续放数据库 |
| 文件路径、大小、哈希、归属 | 云端 PostgreSQL | 增加 COS 对象 key、归档状态和引用关系 |
| 已成功归档的图片、视频 | 云服务器媒体目录 | 腾讯云 COS 私有桶 |
| 新生成图片 | 当前可能仍引用模型服务返回的外部 URL，不保证都已持久归档 | 校验后归档 COS，再作为长期素材使用 |
| 小红书登录状态、平台网页版草稿 | 执行电脑 Chrome Profile | 继续由客户执行电脑保管 |
| 采集缓存、执行证据 | 执行电脑目录 | 增加容量上限、本地缓存索引和清理策略 |

**图片视频不直接塞进数据库，但目前会占服务器磁盘；数据库本身也会随正文、消息、任务和索引增长。两者都需要容量管理。**

当前服务器约 1.7 GB 内存、40 GB 磁盘，不适合作为大量客户素材的长期承载方案。COS 解决素材存储，不替代数据库备份，也不会让存储和流量免费。

## 四、现在同步会不会重复叠加

目前以平台记录 ID 和租户/账号归属更新已有记录，正常重复同步不会无限新增相同记录。

1. 读取账号最新笔记列表。
2. 新笔记、资料不完整的旧笔记补采详情。
3. 已保存且完整的旧笔记跳过详情采集；检查到已知完整列表页时可提前停止向旧页翻页。
4. 评论、私信仍会重新检查，按已有记录更新。
5. 媒体命中缓存时复用，不再重复下载。

需要继续完善的边界：

- 跳过旧帖详情可能遗漏旧帖后续修改、旧帖新评论；应补定期复查机制。
- 当前不保证精确到分页游标的断点续传。
- 在工作台删除内容不等于删除平台原帖，未来同步可能再次采到；需提供“删除本地副本”和“以后不再同步”两个明确选择。
- 素材可能同时被笔记、模板、生成任务引用，删除一个记录不能直接删除共享文件。
- 客户界面应显示新增、更新、跳过、媒体复用、失败数量和覆盖范围，不只显示一个“成功”。

## 五、第三阶段优先事项：COS

### 建议实现

1. 创建与应用地域接近的 COS 私有桶，禁止公开写入。
2. 使用受限服务身份访问。永久密钥仅在服务端保管，不放前端、连接器安装包或聊天文档。
3. 按租户组织对象 key；路径前缀只是组织方式，必须再由后端鉴权及受限上传授权保证隔离。
4. 云端校验租户、文件类型、大小、额度后，签发限定路径和时效的上传授权；大视频采用分片与断点续传，避免经过现有 64 MB 通道限制。
5. 文件成功上传并核对大小/校验值后，再将数据库归档状态改为成功；上传中断不能显示已保存。
6. 图片、原视频、封面、二创图分别保存元数据和来源引用；优先做同租户内容哈希去重。
7. 用户预览/下载通过鉴权后的短时签名 URL；数据库保存稳定对象 key，不把即将过期的签名链接作为永久地址。
8. 草稿执行时获取有效素材下载授权；外部模型生成的图片先及时归档，避免第三方链接过期。
9. 展示客户已用容量、剩余额度和预计增长；超额时给明确提示，保留已上传结果。

### 现有素材迁移顺序

盘点数据库引用与文件 → 上传 COS → 核对数量/大小/哈希 → 验证页面及草稿下载 → 切换读取 → 保留观察期 → 仅回收已确认无依赖的服务器副本。

禁止上传完成就立即删除原目录，禁止迁移时覆盖生产数据库。

### 前置资源

- 腾讯云账号可用、选定地域和私有桶。
- 最小权限 CAM 角色/子账号或临时凭证方案。
- 明确费用预算、容量额度、备份目标和保留时间。
- 凭证通过服务器密钥配置或安全输入方式交付，不写进此文档。

### 验收标准

- A 客户不能上传、下载或删除 B 客户对象。
- 重试同一上传不重复计费计量或创建重复业务记录。
- 大视频中断后能够继续，失败结果真实可见。
- 原有媒体和生成图片可预览、可供草稿执行使用。
- 迁移前后文件数量和校验一致，才允许回收旧副本。

## 六、同步调度、随机抖动与平台限制

### 当前状态

**尚未实现完整随机抖动调度。** 当前有固定等待、同账号任务限制和同电脑同步串行，但不等于完整平台限流机制，也不能保证不触发风控。

之前的 CDP 超时属于浏览器连接问题，没有证据证明它是平台风控。不能把所有失败都当作限流或封禁。

### 建议实施

| 项目 | 建议行为 |
|---|---|
| 最小同步间隔 | 按账号、业务需求及平台允许范围配置，连续点击不重复启动 |
| 随机抖动 | 在基础间隔附近小幅错峰，例如 ±10%–20% 作为待验证设计值；严格不低于最小间隔 |
| 重复点击 | 合并同账号同类型任务，返回已有任务及排队状态 |
| 调度公平性 | 每租户并发/额度限制，避免大客户任务占满全局队列 |
| 浏览器任务竞争 | 统一协调同步、扫码和草稿操作，保护未保存编辑内容 |
| 网络暂时失败 | 有次数上限的指数退避加随机抖动；只自动重试幂等步骤 |
| 429 / 服务端限流 | 尊重 Retry-After，不反复立即重试 |
| 验证码、异常登录、账号限制 | 暂停对应账号，提示人工处理，不自动刷新循环或绕过验证 |
| 平台 403 等异常 | 结合返回内容分类，不能简单一律重试 |
| 草稿结果不确定 | 先核对是否已有草稿，禁止直接再次上传或点击保存 |
| 旧内容复查 | 日常增量为主，另设低频检查修改和新增互动的任务 |
| 离线与重启 | 队列持久化、过期授权重取、取消立即生效，不在恢复上线时瞬间补发所有任务 |

抖动是错峰和降低负载的机制，不用于伪装真人或规避平台检测。不使用代理轮换、设备指纹伪装或验证码绕过。存在可用且获授权的官方接口时优先使用。

具体间隔不能仅靠猜一个数字保证安全，要结合平台规则、实际客户需求及错误率调整。用户应看到下次同步时间、上次结果、排队原因和人工处理入口。

### 验收标准

- 多账号同时加入后启动时间被分散，同账号不会重复执行。
- 断网、429、服务异常触发有上限的退避，不出现重试风暴。
- 队列取消后绝不继续启动；排队不被误判为运行超时。
- 平台要求验证时自动暂停；登录恢复后由明确操作恢复任务。
- 同步和草稿不会互相覆盖未保存内容。

## 七、旧版本与垃圾文件清理

### 当前事实

升级保留旧镜像、旧容器、发行目录和部署前备份用于回退；目前没有完整自动保留上限。媒体、本机缓存、日志、临时文件也没有统一生命周期管理。

旧 SQLite 媒体清理工具已禁止用于 PostgreSQL 主数据目录，避免拿旧引用列表误删新文件。

### 建议策略（待实施）

| 类别 | 保留/清理建议 |
|---|---|
| 应用版本 | 保留当前版本及最近两个验证可用的回退版本；清理前检查容器和任务引用 |
| 升级备份 | 建立分层保留和异地副本；不能简单按“旧”删除唯一可恢复备份 |
| 无引用素材 | 先软删/隔离，建议保留 7–30 天；到期再次查引用后物理删除 |
| 失败上传 | 根据上传会话状态和期限清理分片，避免删掉仍在断点续传的文件 |
| 本机缓存 | 按容量上限和最近使用时间回收；上传未完成、执行中素材必须保留 |
| 日志和执行证据 | 滚动归档、脱敏、限定保留时间，重要审计采用独立规则 |
| 登录目录和密钥 | 不作为普通垃圾自动清理；注销、撤销与迁移走专门流程 |

首次清理先输出可审查清单：文件归属、占用空间、删除理由、依赖、恢复方式。只针对本系统资源，不执行影响同服务器其他网站的无差别清理。

数据库业务记录删除、数据库空间回收、对象文件删除是三件不同的事。不得把 VACUUM 或 Docker prune 当作客户业务数据清理方案。

## 八、后续业务与客户交付

### 模板库与二次创作

- 批量上传有使用权的历史素材，建立标签、分类、版本、来源与授权说明。
- 文案模型、生图模型分开选择与保存，仅提供真实支持的能力。
- 参考图二创只调用确实支持参考图的接口。
- 用户提出的强度 0.55–0.7 不能直接当作跨模型通用相似度：各服务参数含义不同，需映射、预览和人工选择。
- 保存原素材、模型/参数、生成结果、草稿任务的关联；生成结果自动回流素材库。
- 保留人工审核，草稿与公开发布严格区分。

### 安装器与本地缓存

- Windows/macOS 安装器内置运行时、Chrome 检测、配对界面、自启动、诊断和升级/回退。
- 实际签名/公证需要对应开发者凭证；源代码压缩包不等于客户安装器。
- 本地 SQLite 用作缓存索引、待上传队列、执行回执，不把整套云端数据默认复制到每台电脑。
- 明确删除标记、版本冲突、离线恢复和磁盘额度；云端仍是业务主数据。
- 新电脑重新配对并按需要扫码，不能承诺浏览器 Cookie 跨机直接有效。

### 运维与容量

- 每日数据库备份、媒体对象清单、异地加密副本及密钥独立保管；建议保留 7–30 天，具体按恢复要求确定。
- 规定可接受的数据丢失时间（RPO）与恢复耗时（RTO），定期在独立环境恢复验证。
- 监控磁盘、数据库、连接器离线、任务积压、模型失败、备份失败、证书有效期。
- 完善服务端审计、软删恢复窗口、私信线索创建和权限管理入口。
- SQL 分页、全设备调度、租户额度与模型费用预算必须随客户增长完善。
- 4 核 8 GB /100 GB 可作为试运营压测起点，不是客户容量承诺；大量客户前拆分数据库与应用，按实际负载测试扩容。
- 以 10/50/100 活跃客户及明确的账号数、同步频率、素材增量做场景压测；不能仅凭客户总人数估容量。

## 九、建议执行顺序与交付门槛

1. **先盘点**：当前云盘、数据库、媒体、旧镜像、备份、缓存分别占多少；明确回退点和预算。
2. **接 COS 并加额度**：先迁移/验证，后回收服务器副本；同时建立备份与容量告警。
3. **完善调度**：抖动、限流退避、任务合并、统一设备锁、取消和重启恢复。
4. **完成安全清理**：对象引用、恢复期、旧版本与缓存保留上限。
5. **完善素材二创闭环**：模板上传、参考图参数适配、审核、草稿、结果回流。
6. **制作客户安装器**：在一台全新 Windows 和一台全新 Mac 上实测配对与双账号流程。
7. **正式多客户验收**：跨租户攻击测试、故障恢复、负载与费用测试，输出运行手册和验收证据。

每次交付必须同时列明：真实公网版本、通过测试、已知限制、回退方式。不得用“按钮已实现”代替实际业务成功，也不能把阶段二完成解释为所有商业化需求完成。
