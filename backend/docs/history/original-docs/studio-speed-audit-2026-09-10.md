# 小红书草稿同步对抗式审查

日期：2026-09-10。目标：单图尽量在 12 秒内完成真实草稿同步，完整保留内容、原图、可见操作、账号核对与草稿证据。12 秒为性能目标，不是已证明的每次执行保证。

## 发现和修复

| 问题 | 后果 | 当前处理 |
| --- | --- | --- |
| 大图片的每个 Base64 段分别启动 CLI | 数百次启动使同步达到分钟级 | 单个 BrowserBridge 连接，4 个原有 12 KB 段合并请求，每段长度仍校验 |
| 当前扩展拒绝原生 CDP，另一个原生入口等待 chooser 5 秒后失败 | 每次固定损耗数秒，可能误重传 | 不调用不兼容 chooser；明确不支持且空页面才 DataTransfer 回退 |
| 原生成功但预览略慢就再次传图 | 重复图及未知结果 | 原生成功只等待；部分内容或未知结果停止，保留页面 |
| OpenCLI selectTab 没有激活 Chrome 标签页 | 从工作台发起失败，停留小红书时更快 | macOS 激活唯一已有创作页，先激活后读取 DOM |
| 直接触发控件内部 save 事件 | 字段看似正确，但保存可能无效 | Accessibility 精确识别暂存按钮，按实际 bounds 执行鼠标点击 |
| 重复 execute 在 claim 前改 revision | 首次执行领取失败 | 已启动任务幂等返回，不改 revision，不再启动 |
| 计时漏掉启动、把上传算成预览、18 秒也视为通过 | 性能报告失真 | 分阶段计时，服务端记录请求到回执，严格 12000ms，失测不通过 |
| 草稿标题在页面全局匹配 | 编辑器等同名文本可能假阳性 | 限定图文草稿行并记录 draftId |

未改 OpenCLI 安装包或扩展。没有压缩、替换测试原图，也没有自动公开发布。
