# 分离版本运维补充

本副本未上线。生产是两个镜像：matrix-cloud-frontend 与 matrix-cloud-backend，使用同一明确版本号和各自镜像摘要；发布和回滚必须成对进行。后端 API 仅容器网络可达，前端端口 8080 绑定宿主机 127.0.0.1，由现有 HTTPS 入口 nginx 转发。

使用 compose.prod.example.yaml 前，准备 .env、.env.postgres，设置 MATRIX_RELEASE_TAG。PUBLIC_ORIGIN 和 MATRIX_CLOUD_URL 必须等于真实 HTTPS 工作台地址，DATABASE_URL 或 DATABASE_URL_FILE 指向已恢复并完成 schema version 2 迁移的 PostgreSQL；按 migration 说明恢复媒体、密钥和数据。不要直接用空的新 volume 替换生产 volume。先启动 PostgreSQL 和完成迁移，再启动后端/前端。默认测试 .env 模板不能直接用于生产。

如修改 172.30.83.0/24 网络，Compose 子网、前端固定 IP、frontend/nginx.conf 的受信网关和后端 TRUSTED_PROXY_IPS 必须一起更新。端口 4174 不对公网发布；本机 Docker 开发模板的数据库、密码与卷不可复用于生产。

旧维护发布器只管理单容器，对本架构的发布/回滚已阻止执行。维护服务的读取、修改、检查代码继续保留；双容器部署能力需要上线前由受信部署流程接入并验证。

# 运维指南

## 部署与端口

生产入口使用 Nginx 的 80/443；80 仅跳转到 HTTPS 并提供 ACME challenge。业务容器和维护 MCP 通过本机回环端口提供服务，PostgreSQL、开发端口和连接器调试端口不得暴露公网。部署前将 `deploy/matrix-ingress.conf` 中的模板变量替换为实际域名、证书路径和后端地址。

## 备份与恢复

生产数据库使用 PostgreSQL 原生备份，媒体和模板上传按哈希与引用清单备份。密钥和 MCP 凭证单独加密保存。恢复顺序为：验证快照签名和哈希、恢复数据库、恢复媒体、恢复密钥、启动只读服务、核对用户/工作区/账号/内容/素材/任务数量及媒体引用，再开放写入。迁移期间旧服务器至少保留 48 小时。

生产快照绝不放入普通源码 ZIP；`migration/README.md` 只说明导入顺序，不包含任何真实数据。

## 发布与回滚

发布前运行预检、构建、测试和 Docker 配置检查。部署绑定具体 Git 提交、镜像摘要和验证记录；检查失败不得部署。回滚保留当前版本、最近验证通过的回滚版本和最近 7 天业务备份。数据库迁移必须向后兼容，升级失败先切回旧容器，再按恢复记录处理。

## MCP 运维

仅系统管理员可使用维护 MCP。为每位操作者签发可撤销、最小权限凭证；只读、修改、检查、发布、回滚分别授权。过期确认、越权操作和撤销凭证必须被拒绝。日志只记录操作者、变更摘要、检查结果和脱敏错误，不记录 Token、Cookie 或私钥。

## 清理

验收完成后才清理可重新构建的缓存、重复安装包、无引用旧镜像和过期日志。媒体先隔离至少 3 天，再次核对 PostgreSQL 引用后删除。每次清理先生成清单；检查失败、文件发生变化或无法确认引用时跳过删除。不要清理源码、有效客户数据、浏览器登录目录、密钥和回滚依赖。
