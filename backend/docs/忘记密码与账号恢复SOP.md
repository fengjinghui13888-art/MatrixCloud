# 忘记密码与账号恢复

## 客户操作

1. 登录页点击“忘记密码？”，填写原登录账号。
2. 联系平台管理员核实账号归属，获取一次性恢复码。
3. 粘贴恢复码，自己填写新密码和确认新密码，再点击“重设密码”。新密码至少 12 个字符，UTF-8 不超过 72 字节。
4. 成功后返回登录页，用原账号和新密码登录。原工作区、小红书账号、内容、草稿任务、线索、模型配置均保留；旧登录会话失效。

当前没有绑定邮箱/手机号及邮件/短信服务，不能向任意输入的邮箱发送恢复码，也不能仅凭账号名修改密码。此版本采用管理员核实后发码；不是邮件/短信自助找回。

## 管理后台协助找回（推荐）

1. 打开同一网站的 `/admin.html`，使用超级管理员或有“协助找回客户密码”权限的子管理员登录。
2. 进入“客户管理”，按客户原登录账号搜索，点击“管理”。不要让客户重新注册，否则会进入新的空工作区。
3. 核实身份后，在原成员旁点击“签发密码恢复码”。将完整恢复码通过私密渠道交给本人。
4. 客户在网站登录页点击“忘记密码？”，自行粘贴恢复码并设置新密码。后台无法读取旧明文密码。

管理员后台与客户前台共同使用服务器持久化 PostgreSQL。迁移恢复原库和必要文件后，这一流程继续有效。后台管理员自己的密码可在头像菜单“账号设置”修改；超级管理员忘记密码时由服务器负责人使用下方工具签发恢复码，再在客户入口的恢复表单重设密码，最后返回 `/admin.html` 登录。

## 服务器负责人操作（备用）

核实申请人与账号归属后，在 backend 目录执行（使用该项目的 Python 虚拟环境）：

```powershell
.venv\Scripts\python.exe tools/password_recovery.py --username 客户登录账号 --output data/recovery/本次恢复码.json
```

Mac/Linux：

```sh
.venv/bin/python tools/password_recovery.py --username 客户登录账号 --output data/recovery/本次恢复码.json
```

输出目录必须已存在，文件名必须未使用。把文件中 code 的完整值通过已核实的私密渠道交给账号本人。不要放到公共下载目录、日志、Git 或源码包中。管理员不要替客户填写新密码。

恢复码有 256 位随机秘密，有效期 15 分钟，只能成功使用一次。再次签发使同账号旧码作废；数据库只保存秘密的 SHA-256 摘要。过期后重新生成到新文件。不要将工具做成未认证的公开签发接口。

## 存储与验证

PostgreSQL 使用现有 job 表的 password_recovery 类型保存凭据摘要与生命周期，无需 DDL 升级；SQLite 测试环境使用 auth_recovery。成功消费恢复码、写入密码哈希、撤销会话在同一事务中；PG 行锁和账号级事务锁保证并发仅一次成功。签发与重设写入审计日志。
