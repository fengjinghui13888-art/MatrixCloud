# 矩阵云独立平台管理后台

## 入口与登录

- 客户工作台：`http://127.0.0.1:5173/`
- 平台管理后台：`http://127.0.0.1:5173/admin.html`
- 管理员账号：`matrix-admin`。本机登录信息单独存放在 `backend/data/recovery/platform-admin-login-20261015.json`；不要上传该文件或放进源码包。

平台管理员与客户账号分开。`matrix-admin` 为唯一超级管理员，另可创建最多3个子管理员，每个账号都有独立密码。后台使用自己的 HttpOnly / SameSite 严格会话 Cookie，路径 `/api/platform-admin`，不借用客户登录 Cookie。普通客户及其团队管理员不能访问平台后台；仅凭后端服务令牌也不能登录此管理界面。管理员登录与客户工作台登录互不替换。

## 超级管理员与子管理员

点击侧栏底部的管理员头像或账号区域，可展开 **个人中心、账号设置、退出登录**。个人中心显示当前登录账号、身份和已有权限；账号设置可修改自己的密码，必须验证当前密码并两次输入新密码。保存成功后该账号所有旧会话和未使用恢复码失效，需用新密码重新登录。不会更改其他管理员或客户的密码；初始化登录文件中的旧密码不会随之更新。窄屏时此入口显示在顶部导航下方，菜单向下展开。点击空白区域或按 Esc 可关闭菜单。

超级管理员登录后进入 **管理员管理 → 新增子管理员**，填写登录账号、姓名或备注、初始密码，再勾选权限并保存。初始密码至少12个字符，UTF-8不超过72字节；保存后不显示原密码。子管理员使用同一个 `/admin.html` 入口登录。

子管理员最多3个，已停用账号仍占名额。只有超级管理员能创建、编辑、停用、恢复子管理员及重设其密码；不能把子管理员升为超级管理员。超级管理员不会出现在可编辑的子管理员列表中。所有创建和修改操作都有真实操作人审计。

| 权限 | 允许的操作 |
| --- | --- |
| 查看客户 | 客户概览、客户列表、成员身份与业务数量 |
| 停用/恢复客户 | 改变客户工作区状态，需要同时勾选查看客户 |
| 协助找回客户密码 | 给该客户成员签发一次性恢复码，需要同时勾选查看客户 |
| 查看连接设备 | 设备状态、所属客户、系统版本与最近连接时间 |
| 查看操作日志 | 平台最近100条操作记录 |

快捷模板：客户运营（客户查看、停用恢复、设备查看）、客户支持（客户查看、密码协助、设备查看）、审计查看（客户查看、设备查看、日志查看）。模板可以继续手动调整；全不勾选时该账号能登录，但只能看到“尚未分配管理权限”。

没有授权的页面/按钮不展示，数据请求也不会发送。后端每次请求重新核对账号与权限，直接调用接口、修改页面或伪造权限字段都不会越权。权限修改、停用和密码重设会撤销该账号全部旧会话；下一次操作需重新登录。子管理员不能通过客户工作台登录，也不能用其会话访问客户业务接口。

## 已有数据库升级

新部署的 `sql/postgres-schema.sql` 已包含管理员权限表。已有 PostgreSQL 备份或旧库启动当前后端前，使用数据库迁移负责人账号执行 `sql/004-platform-admin-permissions.sql`，再向运行账号授权 `platform_admin_member` 的 SELECT、INSERT、UPDATE。Mac 开发 SOP 已把004放在恢复备份后、运行权限脚本前。应用运行账号不会自动建表，缺少升级时启动会明确提示。

权限表强制行级隔离，仅平台所属工作区可访问。最多3名子管理员由事务锁保证，并发创建不能绕过限制。SQLite 测试/旧项目迁移也会保留子管理员身份和权限；生产继续使用 PostgreSQL。

## 功能

### 客户历史记录（超级管理员）

在“客户管理”搜索原客户账号，点击“管理”，可在“客户历史记录”选择该客户的小红书账号。笔记记录、评论记录、私信记录各自分区，显示已保存正文、时间和本地图片；评论标明所属笔记，私信区分收到和发出。列表固定高度滚动，每页最多12条，支持分页与刷新记录。

这里只读取矩阵云数据库与已保存素材，不跳转小红书、不调用客户电脑连接器、不主动采集最新数据；未保存的记录不会凭空补齐。客户停用后，超级管理员仍可查看其已有记录。客户工作台不增加这个平台管理入口，不发送查看通知；查看操作写入平台审计，普通子管理员无权访问。记录接口不返回模型密钥、浏览器目录或登录凭证，图片通过同一管理员认证与客户归属校验后访问。

2026-10-15 验证：相关前端9项通过，相关后端7项通过（含独立 PostgreSQL 同记录ID跨客户隔离）；增加评论来源后，内容相关两项再次通过，TypeScript和生产构建通过。浏览器已查看真实客户笔记、评论与私信；390宽度未见整页横向溢出，未触发实时小红书同步。

1. **平台概览**：客户工作区、启用中的客户、接入的小红书账号数与在线设备数；不把平台自身工作区计入客户统计。列表包含当前数据库中已有的历史验收工作区，并不等同于付费客户数。
2. **客户管理**：按工作区名称/登录账号搜索，按状态筛选；查看客户成员、权限及业务记录数量。不会展示客户密码、模型密钥、浏览器登录凭证。
3. **停用/恢复客户**：停用时该客户成员旧会话撤销，数据保留；恢复后成员重新登录。平台所属工作区不能停用。操作前有确认，结果写入审计。
4. **协助找回密码**：在客户详情选择成员，签发 15 分钟一次性恢复码。核实归属后通过私密渠道交给本人，客户在工作台“忘记密码”自行设置新密码。重新签发会使上一次未使用的码作废；切换页面或退出后不再展示恢复码。
5. **连接设备**：查看设备所属客户、系统、版本、在线/离线/撤销状态与最近连接时间。
6. **操作日志**：平台管理员最近 100 条登录、客户停用/恢复、恢复码签发记录；后台不显示密码或密钥。

## 技术与目录

与 AI 自动获客系统统一：React + TypeScript + Vite，Python + FastAPI，PostgreSQL。管理后台没有另起 Node 服务，也没有增加生产数据库。

```text
frontend/
  index.html               客户入口
  admin.html               管理员入口
  admin/                   独立管理界面
  src/styles/product-tokens.css  共用产品配色/圆角变量
backend/
  app/platform_admin.py    平台管理接口
  app/auth.py              统一认证与权限校验
  app/recovery.py          一次性密码恢复
  tools/bootstrap_admin.py 仅服务器本机初始化管理员
```

主目录继续只有 frontend/backend 两个业务文件夹。管理端与客户工作台共用颜色/圆角变量：灰蓝背景、白色卡片、黑色主按钮。管理端独立打包入口，客户入口不加载管理页面代码。

## 启动与部署

沿用现有 PostgreSQL、后端、前端启动流程，不需要多启动一个管理服务。`pnpm build` 同时输出 `dist/index.html` 和 `dist/admin.html`。生产环境部署完整 dist，反向代理 `/api` 到现有 FastAPI，并使用 HTTPS、正确的 PUBLIC_ORIGIN 和持久化 PostgreSQL；不要只上传 index.html。

新环境尚无平台管理员时，在 backend 中执行：

```powershell
.venv\Scripts\python.exe tools/bootstrap_admin.py --username matrix-admin --output data/recovery/管理员登录信息.json
```

Mac/Linux 使用 `.venv/bin/python`。输出目录必须已存在，输出文件必须未使用。工具生成随机密码，只写入本机文件，并记录 `data/work/grey/platform-owner` 标识；创建后重启后端。已经存在平台管理员时工具拒绝再次初始化，防止覆盖或抢占账号。

忘记管理员密码时由服务器负责人使用 `tools/password_recovery.py` 签发恢复码，不能重新初始化或修改数据库明文密码。客户页的找回流程也适用于平台管理员设置新密码，之后仍回独立管理入口登录。

源码包不带登录凭据、数据目录和签名私钥。原私有数据 ZIP 仍是历史快照，不包含本次新建的平台管理员；迁移新环境时应恢复适当的最新 PostgreSQL 备份及私有配置，或按流程初始化管理员。
