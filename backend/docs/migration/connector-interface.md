# Python connector integration contract

`app.protocols`: `PROTOCOL_VERSION=4`, `CONNECTOR_VERSION='4.0.0'`, `CAPABILITIES`, `CONNECTOR_PLATFORMS` (original id/label/filename/source dictionaries), `MAX_RPC_ACTIVE=8`, `MAX_RPC_BYTES=67108864`, `RPC_CHUNK_BYTES=49152`, `MAX_WS_BYTES=8388608`.

`valid_connector_command(method:str,path:str,body=OMITTED)->bool` (alias `validate_rpc`) preserves protocol 4's allowlist. Omitted body differs from JSON null or `{}` for account operations. `valid_xhs_event(dict)->bool`, `valid_xhs_subscriptions(list)->bool`, `valid_profile`, `valid_id`, `valid_uuid` implement existing contracts.

`connector.server.create_connector_app(root:Path,cloud_url:str='',port:int=47821)->FastAPI`; ASGI state `app.state.connector` owns isolated runtime. CLI aliases `python -m connector` and `python -m connector.launch`. Options: `--data-dir PATH --cloud-url ORIGIN --port 47821 --device-name NAME`, `--pairing-code CODE` for direct recovery, `--pair` for interactive recovery, and `--onboard` to open the workbench authorization page. Existing protocol4 listeners receive authenticated `/reconnect`; foreign/old listeners are never replaced.

Factory lifespan starts the paired WS/heartbeat, or creates a 10 minute nonce for an unpaired configured origin. GET `/` presents the corresponding workbench authorization link. `/onboarding` accepts the original nonce+8-digit-code GET/form handoff, exact origin/referrer rules, five failures maximum and one successful use. GET `/health` is public; `/verify`, `/reconnect`, `/cleanup`, `/accounts/:id/{login,state,connect,image,remove,cancel,resume,safety}`, `/studio` and `/sync` require the persisted local bearer token and a loopback Host. Account `state` never launches or navigates a browser.

Cloud WS `/api/connector/channel`, `Authorization: Bearer deviceToken`, no redirects. Cloud sends `{type:'request',id,method,path,body?}`; connector sends `{type:'head',id,status,contentType}`, `{type:'chunk',id,data:base64}`, `{type:'end',id}` or `{type:'error',id}`. Cloud cancel `{type:'cancel',id}` cancels RPC transfer; browser job stop uses its explicit `/cancel` route. `watch` carries `subscriptions`; connector emits `{type:'event',event}` and only deletes persistent replay entry after `{type:'event-ack',eventId}`. Device/revocation codes 4000/4001/4002 and HTTP 401/403/426 stop reconnect and cancel work.

Pairing POST `/api/connector/register`: `{code,deviceName,platform,version:'4.0.0'}` -> `{deviceId,deviceToken,workspace}`. Heartbeat POST `/api/connector/heartbeat` -> `{device}`. Token is stored only after validated response and atomic replace, bound to issuing cloud origin.

Studio request `{runId,taskId,profile,apiBase,token,startedAt}` is accepted only against paired cloud origin, UUID identifiers, profile and run-scoped token. Calls existing GET `/api/studio/<taskId>`, POST `/api/studio/<taskId>/{claim,progress,receipt}`, GET `/api/operations` and scoped `/api/studio/<taskId>/media/<filename>` endpoints. Duplicate runId returns receipt; restart or uncertain upload blocks automatic repetition.

No real platform/account, production, running-port changes or browser installation are part of migration validation.

## Execution and retained local formats

`BrowserRuntime` discovers the original Chrome locations, `CHROME_BIN`, Chrome/Edge fallback on Windows/Mac/Linux, and optional `MATRIX_CHROME_PATH`. Login directly launches only the native browser process with its existing account profile (no shell), then Python Playwright attaches through a verified loopback CDP websocket. The saved `session.json` browser websocket identity must match `/json/version`. Automation disconnects without closing detached login windows. Browser profile files are never deleted by account removal or cleanup.

The device queue is shared by login, synchronization and draft work. It bounds pending work to ten tasks, serializes desktop actions, persists old `studio-jobs/<runId>.json` and `sync-jobs/<jobId>/{input,state,result}.json` formats, and blocks orphan running receipts after restart. Running cancellation returns `stopping,stopConfirmed:false` until worker cleanup; queued cancellation returns a confirmed stop. Lease expiry/epoch change, HTTP401/403/429, visible verification/restriction, and revoked pairing stop subsequent operations. Account resume requires explicit confirmation and an elapsed cooldown.

Draft callbacks retain original paths. Evidence remains at the connector root's parent `studio-executions/<taskId>.json`, `<taskId>-<runId>.json`, and `<taskId>.approved.json`. Approved image count remains 1–12. The native upload is invoked once; compatibility injection requires a definitive unsupported native method and an immediate empty-page check. Timeouts/disconnects and partial uploads do not retry. Unconfirmed upload evidence stays blocked across new run IDs. Success requires exact approved body/title/native-topic links, ordered uploaded file IDs, persisted IndexedDB content and a unique visible draft row. The executor only clicks the visible draft button; it never publishes.

Sync checkpoints use `{account,notes,comments,messages}` and set state `checkpoint:true`. Final snapshots add `coverage` (notes/comments/messages), `loginRequired`, `evidence` (creatorHandle/webHandle/responses/errors), and `media` (total/saved/cached/failed/errors). MediaAsset uses original `{id,kind,index,sourceUrl,path,bytes,sha256}`, with account/date/kind/note/file paths. Incremental comments/messages exclude known IDs; only verified creator-list ownership or a baseline bound to both currently authenticated identities can authorize note/comment imports. Missing detail or pagination evidence remains explicitly partial. Media bytes and hashes are preserved; transfer paths are validated against the task's own result and local root.

External draft image destinations reject private/reserved DNS results and pin the TLS connection to the approved public IP. Scoped cloud media URLs receive the run token; external image URLs never receive it. XHS archive downloads accept only platform/CDN domains, validate every redirect, image/video headers, path containment, hash metadata, and size/time limits. Only read-only downloads retry transient errors.

Browser CLI entrypoints: `python -m tools.browser.studio_executor TASK_ID`, `python -m tools.browser.xhs_sync JOB_ID --root ROOT`, `python -m tools.browser.xhs_qr_login ACCOUNT_ID {login,state,image}`. They use Python directly and original environment names. Python Playwright includes its upstream bundled driver as a dependency; no hand-written Node backend/bridge is used and users need no separately installed Node runtime.

## Migration validation

Connector tests use temporary files, injected native browser launchers/CDP responses, HTTP MockTransport and synthetic DOM/network contexts. They cover protocol4 allowlists, pairing and revocation, bounded RPC frames, event replay/ACK and rebinding, no nickname identity inference, QR lifecycle, shared queue cancellation, restart receipts, full 12-image draft confirmation, repeated-run unknown-save protection, incremental sync/checkpoints/followers/media, path/SSRF/cleanup protections and exact original bytes. Real Windows/Mac/Linux QR login, live platform sync/draft acceptance, and versioned installer/signing acceptance remain separate pending checks. No mocked workflow is described as a real-platform acceptance result.
