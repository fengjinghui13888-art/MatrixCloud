# Python services integration contract

All methods are synchronous except model network methods (`async chat`, `async images`, `async edit_image`, `async probe`). JSON dictionaries retain camelCase fields. Failures raise `ServiceError(message, status=400)` (a ValueError subclass); auth uses the exact 401/403/409/429 semantics. Storage operations are transactionally serialized and scope bound.

`Services(settings)`: `.auth: Auth`, `.for_workspace(workspace: str) -> Scope`, `.close()`; rejects invalid/disabled workspaces. `Scope` attributes: `.workspace`, `.root: Path`, `.store`, `.creation`, `.publish`, `.studio`, `.templates`, `.models`, `.billing`, `.assets`. Owner uses settings.data_dir, other scopes use data_dir/workspaces/UUID.

`Auth`: `configured() -> bool`; `identity(cookie_header: str) -> dict|None`; `session(cookie_header) -> dict`; `profile(cookie_header) -> dict`; `setup(input:dict, old_cookie='', ip='127.0.0.1', local=True) -> dict`; `register(input:dict, old_cookie='', ip='unknown') -> dict`; `authenticate(input:dict, old_cookie='', ip='unknown') -> dict`; each credential operation returns `{...identity, token: str}` and API removes token before JSON and sets `zhixu_session` HttpOnly Strict Path=/api 8-hour cookie. `issue(username, old_cookie='') -> str`; `logout(cookie_header) -> dict`; `update_profile(cookie_header,input) -> dict`; `active(workspace) -> bool`; `same_origin(origin, host='', scheme='http', sec_fetch_site='') -> bool`; `role_allows(role,method,path) -> bool`; `team(identity) -> dict`; `create_member(identity,input) -> dict`; `update_member(identity,username,input) -> dict`; `audit(identity) -> dict`; `tenants(identity) -> dict`; `update_tenant(identity,id,input) -> dict`.

`Store`: `add_account(account)`, `delete_account(account_id)`, `delete_note(account_id,note_id)`, `delete_notes(items)`, `delete_lead(id)`, `delete_leads(ids)`, `delete_follow_up(id)`, `delete_follow_ups(ids)`, `clear_content(account_id=None)`, `import_snapshot(input)`, `list_accounts()`, `list_notes(filter=None)`, `list_comments(filter=None)`, `list_messages(filter=None)`, `list_leads(filter=None)`, `list_members()`, `list_follow_ups(lead_id)`, `list_sync_runs()`, `get_comment(id)`, `create_lead(input)`, `create_lead_from_comment(comment_id,input)`, `update_lead(id,patch)`, `add_follow_up(lead_id,body,author)`, `update_comment(id,patch)`, `upsert_notes(notes)`, `record_sync(run)`. Identical old payload/result shapes.

`CreationQueue` / `PublishQueue`: `list()`, `get(id)`, `create(input)`, `claim(id)`, `complete(input)`, `delete(id)`, `delete_many(ids)`; Publish adds `cancel(id)`. Creation preserves exact 1–12 imageCount validation. Published/draft success requires real evidence. No restart requeue of claimed tasks.

`Studio`: `list()`, `get(id)`, `create(input) -> {task,fresh}`, `update(id,revision,patch)`, `delete(id)`, `delete_many(ids)`, `delete_by_account(account_id)`.

`Templates`: `list()`, `get(id)`, `published()`, `create(input)`, `update(id,input,expected)`, `publish(id,expected)`, `unpublish(id,expected)`, `delete_many(ids)`; personal methods `mine()`, `upload(input)`, `bulk_delete(ids)`; `file(key, thumbnail=False) -> Path|None`.

`Models`: `read()`, `summary()`, `profiles()`, `save(input,as_new=False)`, `activate(id)`, `async chat(prompt,max_tokens=512,transport=None)`, `async images(prompt,count=1,size='1024x1024',transport=None)`, `async edit_image(prompt,reference,strength=.6,transport=None,size='1024x1024')`, `async download_image(url) -> data URI`, `async probe(input=None)`. AES-GCM Node IV(12)/tag(16)/ciphertext layout unchanged. `public_https_json(url,headers,body)`, `download_model_image`, `call_model`, `generate_images`, and `edit_images` are exported from models.py. Transport resolves and pins an approved IPv4 address, verifies the original TLS hostname, follows no redirects, bounds decoded response sizes and uses a total 120/180/30-second deadline for text/image/download respectively. Inject a synthetic async transport for tests; no automatic retry is performed.

`Billing`: `create_api_key(name)`, `verify_api_key(secret)`, `revoke_api_key(id)`, `debit(input)`, `create_topup_order(plan)`, `complete_topup(order_id,payment_reference)`, `summary()`; existing 3000 fresh balance and pro=5000/team=20000/basic=1000 unchanged, never coupled to creative model task limits.

`Assets`: `file(relative,account_id,note_id) -> Path|None`; note ownership is additionally verified by the API before exposing paths. `templates.file` owns template-media access.

PostgreSQL uses the existing normalized schema, tenant predicates and `SET LOCAL app.tenant_id` on each business transaction; does not auto-run DDL or migrate legacy files. Missing schema, permissions, encryption keys and connectivity errors remain visible failures.

`Postgres(url)` validates existing schema version 2 immediately. `validate_schema() -> {version,tables}`, `transaction(tenant)` is a context manager yielding a psycopg connection, `rows(tenant,sql,params=())`, `active(tenant)`, `audit(tenant,actor,action,target,result)`, `close()`. Each transaction owns and closes its connection. `PostgresStore._load(connection)` and `_persist(connection,before,state,validate_owners=True)` support explicitly authorized offline migration tools inside their existing transaction. `_persist` writes separate normalized entity rows including `team_member`; default live mutations validate owners against enabled same-tenant app users. Only offline migration may request legacy owner-ID preservation explicitly. Live snapshot imports reject deleted/unconnected accounts inside the mutation transaction.

Public published templates intentionally come from owner scope. Personal upload/mine/media/reference generation use the authenticated workspace scope. `Templates.references(ids) -> list[data URI]` and `Templates.save(data,name) -> media URL` support the studio reference pipeline. `Scope.workbuddy` preserves the legacy `create(input)`/`list()` awaiting-browser task JSON service; retired HTTP routes remain an API concern.

Validation: core/business service tests cover legacy SQLite schemas/payloads, scrypt and bcrypt, old AES-GCM single-profile files and missing-key refusal, concurrent claims and atomic bulk deletion, duplicate request protection, studio revision conflicts, snapshot merge/cascades, personal templates and original legacy PNG, thumbnails and protected media, role/member/tenant/session revocation, login limits, billing prices and idempotent topups, provider protocol/payload preservation, multipart references, SSRF/private DNS, response limits/deadlines, corrupt data preservation and PG fail-closed/tenant-context boundaries. Final ordinary backend suite: 131 passed. Separately, `tests/test_services_postgres_integration.py` ran against an independent PostgreSQL 16.15 loopback cluster with explicit TEST_DATABASE_URL: 8 passed, no skipped tests. It verified actual v2 schema/RLS/least-privilege roles, auth and tenant revocation, normalized data, concurrent queue claims, Studio revisions, encrypted profiles/templates, persistent sync leases and terminal callbacks, connector pairing/revocation, and transactional offline migration/readback/idempotence. The dedicated cluster is stopped. Live provider/platform workflows remain unverified; all test accounts/media/provider payloads are synthetic. Full evidence and limits: ledger.md.
