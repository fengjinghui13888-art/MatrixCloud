# PostgreSQL 与前后端独立启动

当前本机已完成 SQLite → PostgreSQL 迁移。默认启动使用 PostgreSQL 16.15，数据库为 `matrix`，地址为 `127.0.0.1:5433`。原来的 2 个页面账号、密码和有效会话已迁入；源数据没有平台账号、笔记、评论或任务，因此没有向数据库加入演示业务记录。

本机数据库程序来自 [EDB 官方 Windows 二进制分发](https://www.enterprisedb.com/download-postgresql-binaries)，已核对下载内容 SHA-256；运行目录只提取了 bin/lib/share。

## 独立边界

| 部分 | 目录 / 端口 | 职责 |
| --- | --- | --- |
| React 前端 | frontend / 5173 | 页面、前端依赖、构建产物；通过 HTTP/WebSocket 调用后端 |
| Python API / MCP | backend / 4174 | 认证、业务规则、数据库访问、供应商调用 |
| PostgreSQL | backend/data/postgresql / 5433 | 账号、会话、租户、业务实体、任务、模板、加密模型配置和设备绑定等 |
| 本机连接器 | backend/connector / 47821 | 本机浏览器与平台交互，需要单独启动和授权 |

前端没有数据库密码，也不导入后端源码。开发环境由 Vite 代理 `/api`、`/mcp`；生产前端镜像使用 Nginx 代理，Python 后端不负责提供 React 静态页面。两个目录各有自己的依赖、Dockerfile 和构建上下文；项目根保持两个可见文件夹。

图片、供应商密钥的加密主密钥及部分本机执行状态仍由后端文件目录管理；例如浏览器执行互斥使用本机 SQLite，费用与旧 WorkBuddy 状态使用后端 JSON。这些不是前端存储，也不随前端发布。当前并未把所有文件状态改为 PostgreSQL，也不应据此直接部署多个无共享状态的后端实例。

## 这台电脑怎么启动

1. 双击 `backend/START-BACKEND.bat`，启动 API。当前 `.env` 中的 `LOCAL_POSTGRES=true` 会先启动本项目的已初始化数据库。
2. 双击 `frontend/START-FRONTEND.bat`，启动页面。
3. 浏览器打开 <http://127.0.0.1:5173/>，使用原账号和密码。

也可以双击 `backend/START-ALL.bat`，它只是同时启动两个独立进程的便利入口。前端进程仅收到必要的系统变量和公开的 API 地址，不继承后端凭证。分别启动时，停止后端不会停止前端或数据库；使用 ALL 时关闭启动窗口会停止其管理的前后端，数据库仍独立运行。

数据库可以独立管理：`backend/START-DATABASE.bat`；停止时先退出后端，再运行 `backend/STOP-DATABASE.bat`。数据库没有注册为 Windows 系统服务，不会在开机时自动启动；下一次启动后端时会自动拉起。

在 backend 中运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/local_postgres.py status
.\.venv\Scripts\python.exe -X utf8 run.py server
```

前端单独在 frontend 中运行 `pnpm dev`；`pnpm build` 只构建前端。API 健康检查 <http://127.0.0.1:4174/api/health> 应返回 `storage: "postgresql"`。

## 必须保留

- `backend/.env`：本机配置；数据库密码实际存放在 `data/postgresql/app-url`，由 `DATABASE_URL_FILE` 指向。
- `backend/data/postgresql/cluster`：实际 PostgreSQL 数据文件；`runtime` 是正在使用的数据库程序。
- `backend/data/postgresql/local.json`：本机数据库路径和端口；`owner-url`、`admin-url`、`admin-password` 是离线维护凭证，禁止放入前端或 Git。
- `backend/data/work/grey`：当前后端文件数据及 `postgres-active` 标记；删除数据库配置后，此标记会阻止程序误用 SQLite。
- `backend/data/recovery/pre-postgresql-20261013`：停机时原数据的 23 文件备份和 SHA-256 清单。

旧 `data/preview` 已标记为已迁移，不再作为独立 SQLite 数据集启动。Git 和 Docker 构建均排除 `.env`、数据库、凭证与备份。

## 换电脑或部署

仓库不会携带本机数据库和密码。换电脑时要单独安装 PostgreSQL、恢复数据库备份和后端文件数据，再配置应用连接；仅复制代码不会带走数据。

容器示例分别使用 `.env.docker.example` 和 `.env.postgres.example`。数据库管理员凭证只交给数据库服务；应用连接使用权限受限的 `matrix_app`，并设置 `DATABASE_REQUIRED=true`。前端、后端分别构建，数据库仅加入 backend/postgres 的内部网络，不加入前端网络、不发布数据库端口。

容器启动不会自动初始化应用表。必须在空目标数据库创建应用角色，由迁移所有者显式执行 `tools/migrate_postgres.py <已备份的源目录> --offline-confirmed --initialize-schema`，随后使用应用凭证启动 API。迁移所有者需要建立 schema、授权和跨租户读取的权限；应用角色不得拥有 superuser、createdb、createrole 或 bypassrls 权限。已使用中的数据库不能直接套用空库初始化步骤。

本次只切换本机项目，没有改动远程生产环境；Docker 示例尚未完成实际容器构建验收。

## 回滚原则

迁移前备份保持只读。若需要回滚，先停应用并保存切换后 PostgreSQL 的最新备份；在新的独立目录恢复迁移前备份，并显式关闭 `DATABASE_REQUIRED`、`LOCAL_POSTGRES` 和数据库 URL 配置后启动旧数据。不要直接删当前 `postgres-active` 标记，不要在两套数据库同时接受写入。切换后产生的新数据不会自动出现在旧 SQLite 中。
